# تطبيق إدارة المبيعات بالتقسيط

تطبيق أندرويد بلغة **Kotlin** وواجهات **Jetpack Compose**، لإدارة عمليات البيع بالتقسيط لمتجر محلي:
تسجيل العملاء، إنشاء فواتير بيع بالتقسيط، توليد جدول أقساط تلقائي، متابعة الأقساط المتأخرة، تقارير،
وطباعة فواتير/وصولات عبر **طابعة حرارية ESC/POS بعرض 80مم** (تدعم الاتصال عبر **بلوتوث** أو **USB**)
مع **معاينة كاملة قبل الطباعة الفعلية**.

## 1) فتح المشروع في Android Studio
1. ثبّت أحدث إصدار من **Android Studio** (Koala أو أحدث).
2. اختر **Open** وحدد مجلد المشروع `InstallmentSalesApp`.
3. عند أول فتح سيقوم Android Studio تلقائياً بإنشاء ملفات Gradle Wrapper الناقصة (gradlew, gradle-wrapper.jar)
   وتنزيل جميع مكتبات Compose/Room المطلوبة (يتطلب اتصال إنترنت في أول مرة فقط).
4. انتظر حتى تنتهي عملية **Gradle Sync** من شريط الحالة أسفل الشاشة.

## 2) تصدير ملف APK
- من القائمة: **Build ← Build Bundle(s) / APK(s) ← Build APK(s)**.
- بعد الانتهاء اضغط على رابط **locate** الذي يظهر لإيجاد الملف الناتج في:
  `app/build/outputs/apk/debug/app-debug.apk`
- لتوليد نسخة موقّعة (Release) جاهزة للتوزيع: **Build ← Generate Signed Bundle / APK**، ثم أنشئ Keystore جديد
  عند أول مرة واتبع الخطوات.

## 3) هيكل المشروع
```
data/           كيانات Room (Customer, Sale, SaleItem, Installment, Payment) + DAOs + AppDatabase
repository/     منطق الأعمال (إنشاء بيع، توليد جدول الأقساط، تسجيل السداد)
printer/        كل ما يخص الطباعة الحرارية ESC/POS (بلوتوث + USB) وبناء الوصل والمعاينة
ui/theme/       ألوان وخطوط Compose
ui/nav/         شجرة التنقل بين الشاشات (Navigation Compose)
ui/screens/     الشاشات: لوحة التحكم، العملاء، بيع جديد، الأقساط، المعاينة، التقارير، الإعدادات
viewmodel/      AppViewModel الذي يربط الواجهات بقاعدة البيانات والطابعة
```

## 4) التخزين المحلي
تُستخدم قاعدة بيانات **Room (SQLite)** محلية على الجهاز، تبقى محفوظة بالكامل حتى بعد إغلاق التطبيق
أو إعادة تشغيل الهاتف، دون الحاجة لأي اتصال إنترنت.

## 5) الطباعة الحرارية (ESC/POS – 80مم)
- تم بناء أوامر ESC/POS يدوياً (محاذاة، خط عريض، قص الورق...) في `printer/EscPosCommands.kt`.
- **البلوتوث**: يدعم بروفايل SPP الكلاسيكي (وهو الأكثر شيوعاً في طابعات الإيصالات الرخيصة).
  قبل الاستخدام، قم بإقران (Pair) الطابعة من إعدادات بلوتوث الهاتف نفسه أولاً، ثم اختَرها من شاشة
  "إعدادات الطابعة" داخل التطبيق.
- **USB**: يتطلب كابل **OTG** لتوصيل الطابعة بمنفذ الهاتف مباشرة. عند أول اتصال سيطلب النظام صلاحية
  الوصول لجهاز USB، وافق عليها ثم أعد الضغط على "اتصال".
- **المعاينة**: شاشة "معاينة قبل الطباعة" تعرض نفس تنسيق الوصل حرفياً (نفس الأسطر والفواصل) بحيث
  تتأكد من صحة البيانات قبل إرسالها فعلياً للطابعة.

> ملاحظة: إن كانت طابعتك بعرض **58مم** بدلاً من 80مم، افتح شاشة الإعدادات واختر "58 مم" وسيتم
> تلقائياً تصغير عدد الأحرف بالسطر (32 بدلاً من 48) لتناسب عرض الورق.

## 6) أهم الميزات المُنجزة
- تسجيل العملاء (اسم، هاتف، عنوان).
- إنشاء عملية بيع بالتقسيط: إضافة عدة أصناف، تحديد الدفعة المقدمة وعدد الأقساط، والنظام يحسب
  قيمة القسط تلقائياً ويولّد جدول استحقاق شهري.
- **خصم / تعديل سعر يدوي وقت البيع مع صلاحية**: من شاشة الإعدادات يمكن تعيين رمز صلاحية (PIN).
  إن كان مفعّلاً، يبقى سعر كل صنف وحقل الخصم في شاشة "بيع جديد" مقفلَين حتى يُدخل المستخدم
  الرمز الصحيح، بحيث لا يستطيع أي موظف تخفيض الأسعار دون إذن صاحب المحل.
- **نسخ احتياطي واستعادة**: من شاشة الإعدادات، يمكن حفظ نسخة من قاعدة البيانات كاملة (كل
  العملاء والمنتجات والفواتير والأقساط) في أي مكان يختاره المستخدم، واستعادتها لاحقاً عند
  الحاجة (بعد تأكيد لأن الاستعادة تستبدل البيانات الحالية بالكامل، ثم يُعاد تشغيل التطبيق تلقائياً).
  كما تم استبدال `fallbackToDestructiveMigration()` بخطوات Migration حقيقية، بحيث لا تُمسح
  بيانات المستخدمين تلقائياً عند تحديثات مستقبلية للتطبيق تُغيّر بنية قاعدة البيانات.
- **شعار المحل**: يمكن اختيار صورة شعار من شاشة الإعدادات، ويُطبع تلقائياً أعلى كل فاتورة ووصل
  (يُطبع فعلياً كصورة نقطية عبر أمر ESC/POS، وليس مجرد نص)، ويظهر أيضاً في شاشة المعاينة.
- **كشف حساب كامل للعميل**: من شاشة تفاصيل العميل، زر "طباعة كشف حساب كامل" يجمع كل فواتير
  العميل وجداول أقساطها وحالتها (مسدد/متأخر/غير مسدد) في وصل واحد، مع إجمالي المبيعات
  والمُحصَّل والمتبقي.
- شاشة العميل: عرض كل فواتيره وأقساطها، تسديد قسط (سداد جزئي أو كامل) مع طباعة وصل فوري.
- شاشة متابعة الأقساط: عرض كل الأقساط غير المسددة، وتمييز المتأخر منها بالأحمر.
- لوحة تحكم رئيسية: ملخص عدد المبيعات، المبالغ المستحقة، والأقساط المتأخرة.
- تقارير: إجمالي المبيعات، المُحصَّل، المتبقي، عدد الأقساط المتأخرة.
- طباعة حرارية ESC/POS (80مم) عبر بلوتوث أو USB مع شاشة معاينة قبل الطباعة الفعلية.

## 7) أفكار لتطوير لاحق (اختياري)
- إضافة نظام تنبيهات (إشعارات Android) قبل موعد استحقاق القسط بيوم أو يومين.
- دعم استيراد/تصدير النسخ الاحتياطي لقاعدة البيانات (ملف .db) عبر مشاركة الملفات.
- إضافة صلاحيات مستخدمين (بائع/مدير) إن كان هناك أكثر من موظف يستخدم التطبيق.
- ربط الطابعة تلقائياً عند بدء التطبيق إن كانت آخر طابعة مستخدمة متاحة.

## 8) رفع المشروع على GitHub
لا أملك القدرة على الاتصال المباشر بحساب GitHub الخاص بك من هنا، لكن يمكنك رفع المشروع بسهولة بنفسك:

1. **افتح المشروع أولاً في Android Studio مرة واحدة** (كما في الخطوة 1) ليقوم تلقائياً بتوليد ملفات
   Gradle Wrapper الناقصة (`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`) — هذه الملفات
   ضرورية لكي يعمل GitHub Actions المرفق في `.github/workflows/build-apk.yml`.
2. أنشئ مستودعاً جديداً فارغاً على GitHub (بدون README أو .gitignore عند الإنشاء).
3. من داخل مجلد المشروع نفّذ الأوامر التالية (استبدل الرابط برابط مستودعك):

```bash
git init
git add .
git commit -m "الإصدار الأول: تطبيق إدارة المبيعات بالتقسيط"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```

4. بعد الرفع، سيقوم GitHub Actions تلقائياً (الملف المرفق `.github/workflows/build-apk.yml`) ببناء
   نسخة APK تجريبية عند كل Push، ويمكنك تنزيلها من تبويب **Actions ← آخر تشغيل ← Artifacts**
   داخل صفحة المستودع — بنفس أسلوب CI/CD المستخدم في مشروعك السابق لقاعة الأفراح.

> ملاحظة: تم تضمين ملف `.gitignore` مناسب لمشاريع أندرويد يستثني مجلدات البناء المؤقتة
> (`build/`, `.gradle/`, `local.properties`...) حتى لا تُرفع ضمن المستودع.

## 8) رفع المشروع وبناؤه على GitHub — بالكامل من الهاتف
تم تعديل ملف `.github/workflows/build-apk.yml` بحيث لا يحتاج المشروع لملفات Gradle Wrapper
(`gradlew`) إطلاقاً — يقوم GitHub تلقائياً بتجهيز Gradle عند كل بناء. هذا يعني أنك **لا تحتاج فتح
Android Studio على كمبيوتر أبداً**، ويمكنك رفع الكود مباشرة من هاتف الأندرويد بإحدى الطريقتين:

### الطريقة الأسهل: تطبيق محرر مع دعم Git (بدون أوامر)
1. ثبّت تطبيق مثل **Spck Editor** (مجاني، فيه دعم Git كامل بواجهة رسومية) من متجر Google Play.
2. افتح المشروع (فك الضغط عن الملف المرفق أولاً داخل مدير الملفات في الهاتف).
3. من داخل Spck: New Project ← Import from folder ← اختر مجلد `InstallmentSalesApp`.
4. من قائمة Git: Init ← أضف Remote برابط مستودعك (مع Personal Access Token بدلاً من كلمة المرور،
   انظر أدناه) ← Commit ← Push.

### الطريقة الثانية: Termux (سطر أوامر، للمستخدم المتمرس)
1. ثبّت **Termux** (يُفضّل من F-Droid لأنه أحدث من نسخة متجر Google Play).
2. داخل Termux:
```bash
pkg install git -y
cd storage/downloads   # أو مسار فك ضغط الملف
cd InstallmentSalesApp
git init
git add .
git commit -m "الإصدار الأول"
git branch -M main
git remote add origin https://TOKEN@github.com/USERNAME/InstallmentSalesApp.git
git push -u origin main
```
(أول مرة نفّذ `termux-setup-storage` للسماح لـ Termux بالوصول لملفات الهاتف)

### إنشاء Personal Access Token (مطلوب بدل كلمة المرور)
من متصفح الهاتف: GitHub ← الصورة الشخصية ← Settings ← Developer settings ← Personal access tokens ←
Tokens (classic) ← Generate new token ← فعّل صلاحية `repo` ← انسخ الرمز فور ظهوره (يظهر مرة واحدة فقط)
واستخدمه بدل كلمة المرور في أوامر git أعلاه.

### بعد الرفع
بمجرد أن يصل الكود لمستودعك، افتح تبويب **Actions** في صفحة المستودع (عبر متصفح الهاتف أو تطبيق
GitHub الرسمي) وستجد البناء يعمل تلقائياً. بعد اكتماله (2-4 دقائق) حمّل ملف الـ APK من قسم
**Artifacts** أسفل تفاصيل التشغيل — كل هذا من الهاتف مباشرة دون الحاجة لأي كمبيوتر.
